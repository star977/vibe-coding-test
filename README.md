# mdnsscan

网络资产测绘 CLI。给定 IP 网段与端口范围，采集范围内设备**主动声明**的服务信息，
含深度标识——型号、固件版本、管理地址等设备自报字段。

> 这不是端口扫描器。输出中的端口不是探测出来的，是设备在服务定位记录里自己报的。

## 快速开始

```bash
go build -o mdnsscan .
./mdnsscan --cidr 192.168.1.0/24 --ports 1-65535
```

无需 root 权限。Go 1.22+ 即可构建。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--cidr` | 必填 | 待测绘网段，如 `192.168.1.0/24` |
| `--ports` | `1-65535` | 端口**过滤**范围。也接受单端口简写 `--ports 5000` |
| `--timeout` | `2s` | 单个地址的总时间预算 |
| `--concurrency` | `256` | 并发探测数，默认值使 /24 可一批打完 |

## 实现要点

完整设计、数据契约与 59 条验收标准见 [DESIGN.md](DESIGN.md)。三个关键点：

**端口范围是过滤器，不是扫描范围。**
设备的自我介绍里自带端口号，流程是「先拿到全部服务 → 再按端口范围筛」。

**深度标识全量透传，不硬编码键名。**
不同厂商的字段各不相同，代码不维护任何键名白名单，收到什么输出什么，
顺序、大小写、重复键一律不动。这是深度能否达标的唯一判据。

**双通道探测。**
主通道对网段内每个地址单播询问；兜底通道发一次全网广播，
捕获那些只监听广播、不响应单播的精简实现设备，其结果再用网段过滤。
广播通道不可用时自动降级为纯单播。

广播通道还会额外补发 22 个常见服务类型的查询，覆盖那些不响应
服务类型元查询的设备。只在广播通道补发——广播整轮只跑一次，
开销可忽略；单播要按地址逐个发送，查询量会随网段规模放大。

## 验证情况

已在真实局域网实测通过：

| 项 | 结果 |
|---|---|
| 深度标识 | 拿到型号、版本、设备标识等自报字段 |
| 性能 | /24 网段 **3.0 秒**完成 |
| 输出可复现 | 连续三次运行逐字节一致 |
| 并发安全 | `go run -race` 零告警 |
| 参数校验 | 10 类非法输入均明确报错、退出码 2、无 panic |
| 空结果 | stdout 为空，退出码仍为 0 |
| **多设备** | 3 台设备乱序输入后按 IP 正确排序，各自独立成块 |
| 取消传播 | 预算设 30s，`Ctrl-C` 后实测 **0.15 秒**收尾 |
| 并发受控 | 阻塞桩实测并发恰为设定值；超上限自动截断并提示 |
| 协程泄漏 | 探测结束后协程数回落至基线 |
| 大网段 | `/8` 的内存分配为常量级，不随网段规模增长 |
| 自动化测试 | **61 个用例、112 项断言全过，语句覆盖率 95.5%** |

## 测试

```bash
go test -race ./...            # 全量，含竞态检测
go test -cover ./...           # 覆盖率
go test -run Integration ./... # 仅集成层
go test -run E2E ./...         # 仅端到端层
```

分四层，失败时能直接定位问题所在：

| 层次 | 手段 | 回答的问题 |
|---|---|---|
| **单元** | 直接调用纯函数 | 单个函数的边界与异常输入是否处理正确 |
| **组件** | 内存中构造已解包的消息 | 多个函数协作的逻辑是否正确 |
| **集成** | 本地假响应端 + **真实 UDP 套接字** | 收发、报文编解码、三段式问答是否真的可用 |
| **端到端** | 进程内 `run()` 与**真实子进程** | CLI 契约、退出码、流分离是否符合约定 |
| **健壮性** | 注入故障、投递恶意报文、构造滞留目标 | 异常与攻击场景下是否仍然可靠 |

集成层会在本地临时端口起一个按 DNS-SD 规则应答的假响应端，
端到端层会先构建二进制再作为独立进程执行——
**两者都不依赖真实局域网，可在任意机器上复现**。

重点覆盖了线上难以构造的场景：

- **解析炸弹**：手工拼出自指与互指两种压缩指针环，验证不死循环、不崩
- **内存放大**：声明 65535 条记录的报文、灌包 400 条、60 KB 巨型包
- **网络不可用**：区分「连不上」与「没发现」，前者必须明确告警
- **滞留目标**：一个目标耗满预算，不得拖慢其余地址
- **活动面**：记录全部 dial 目标，断言均在指定网段内且次数完全吻合
- **性能门限**：254 个本地黑洞目标实测 107ms，与网络无关，可复现
- 广播降级、取消传播、并发上限精确测量、控制字符防注入、
  200 次重复渲染的一致性

## 已知未完成

时间所限，以下按设计文档 §9.8 的优先级主动放在后面，未实现或未验证：

- **独立源地址的多设备测试需要环回别名**。用例已写好，macOS 默认只
  分配 127.0.0.1 故会跳过并打印启用命令；Linux 默认整个 127/8 可用，
  会直接运行
- **多台真实设备同时响应广播**：组播通道的代码路径已由集成测试覆盖，
  但真实组播环境下多设备并发应答无法在单机自动化中复现
- **真实网络耗时**：已提供与网络无关的可复现门限，但真实局域网计时
  依赖环境，只能手工验证
- **种子服务类型的增量效果**：集成测试已确认种子查询真的发到了线缆上，
  但「因此多发现了设备」需要一台不响应元查询的真实设备才能证实
- 单播通道在元查询无响应时即放弃该地址，这是为控制大网段耗时所做的
  取舍；此类设备依赖广播通道兜底，详见 DESIGN.md §10

## 已知问题

设备自报值本身可能含逗号（实测 `model=Mac17,3`、`cn=0,1,2,3` 极为常见），
与用作分隔的逗号存在歧义。因题目示例同样以逗号连接，
判断参考实现存在相同歧义，故选择保真原样输出，不做转义。详见 DESIGN.md §10。

## 使用声明

本工具仅供在**已获授权的网络**中进行资产盘点使用。
它只向 `--cidr` 指定范围发包，不主动出网、不上报任何数据。
